# 115 Netdisk

The `115netdisk` backend accesses a [115 Cloud](https://115.com/) account with a
saved client Cookie session. It supports directory listing and creation,
SHA-1 hashes, single and multipart uploads, rapid uploads, ranged downloads,
server-side copy and move, directory moves, duplicate files, and storage quota
queries.

Paths use the usual `remote:path` syntax and may contain nested directories.

## Configuration

Run `rclone config`, create a remote, and select `115netdisk`. Choose either
QR authorization with the 115 mobile app or paste an existing Cookie.

```text
No remotes found, make a new one?
n) New remote
n/s/q> n

Enter name for new remote.
name> 115

Option Storage.
Storage> 115netdisk

Edit advanced config?
y) Yes
n) No (default)
y/n> n

Select authorization type
1 / Scan with the 115 mobile app
2 / Paste an existing Cookie
auth_type> 1
```

Rclone displays a QR code in the terminal. Scan it with the 115 mobile app
and confirm the login. Rclone saves the resulting Cookie in its configuration.
The saved Cookie grants access to the account. Keep the configuration file private.

### Paste a Cookie

Choose authorization option `2` and paste a Cookie header or cookie dictionary
JSON at the `cookie` prompt. Include UID, CID, SEID, and all additional Cookie
values returned by login. Rclone validates the Cookie format before saving it.

```text
auth_type> 2
Paste your 115 Cookie header or cookie dictionary JSON
cookie> UID=your_uid; CID=your_cid; SEID=your_seid
```

To configure the remote manually, set `cookie` to the complete Cookie from
your logged-in 115 session:

```ini
[115]
type = 115netdisk
cookie = UID=your_uid; CID=your_cid; SEID=your_seid
```

The backend reads the saved Cookie when a filesystem instance is created.
An expired or revoked session requires a new login.

```sh
rclone lsd 115:
rclone about 115:
rclone copy ./documents 115:documents
```

## Client identity

The protocol version defaults to `37.3.1`. `user_agent` can override the
macOS client UA used for both API and file-content requests. Each filesystem
uses its own HTTP configuration, so this identity does not change other
backends.

Cookie-authenticated API requests are limited to five requests per second
per filesystem instance.

## File behavior

115 Cloud permits multiple files with the same name in one directory. Normal
rclone uploads replace the selected destination object; `PutUnchecked` may
create a duplicate. Upload replacement and server-side copy or move operate
on confirmed object IDs. Server-side copy and move require
matching filename extensions. Directory moves fail when the destination
directory already exists.

The backend requires a known, positive upload size. Existing empty files
can be read; uploading empty files returns `ErrorCantUploadEmptyFiles`.
Modification times are read from the server, and setting modification times
is unsupported.

Downloads retain the Cookie associated with each signed URL and validate
ranges. A new download-address request after deletion can fail while an
earlier signed URL remains readable until the content service rejects it.

## Uploads

115netdisk verifies uploads with SHA-1 and uses rapid upload when the content
already exists in 115 Cloud. Files larger than 20 MiB use multipart uploads.
The default part size is 20 MiB and increases for very large files. Each file
uploads up to four parts concurrently.

Seekable inputs supporting independent range reads are uploaded directly. Other
inputs buffer each active part in rclone's memory pool, using up to 80 MiB per
file with the default part size. `--use-mmap` controls the pool allocation
method. Parts larger than 20 MiB and uploads with a positive
`--max-buffer-memory` limit use the system temporary directory.
Temporary disk usage for these parts is bounded by four times the part size.
When the source cannot supply a SHA-1 hash, a stream may also be staged in full
to calculate it before uploading.

Use `--transfers` to control the number of files uploaded simultaneously.

## Recycle bin

Removing files and directories sends them to the account recycle bin.
The following command permanently deletes every item listed in the account
recycle bin, including items outside the configured root:

```console
rclone cleanup 115:
```

This operation cannot be limited to a directory and cannot be undone. Accounts
with a security key require the `security_key` option.

## Limitations

- Empty files cannot be uploaded.
- Uploads require a known size.
- Modification times cannot be changed.
- Server-side file copy and move require matching filename extensions.
- Directory moves require the destination directory to be absent.
